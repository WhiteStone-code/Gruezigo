# UX Audit — GrüeziGo

Scope: design/token-level critique only, based on current Tailwind config, `index.css`, `NavBar.jsx`, `Dashboard.jsx`, `levels/index.js`. Grouped, actionable, implementable directly.

## Más colorido y divertido, sin ser infantil

- **`.card` is a single flat white box everywhere** (`index.css`) — every card (dashboard stat, lesson item, culture note) looks identical. Add a `card-accent` variant per section: `border-l-4 border-l-wood-400` for culture/vocab cards, `border-l-4 border-l-cheese-400` for gamification/streak cards, `border-l-4 border-l-alp-400` for grammar/neutral cards. Keeps the same base `.card` shadow/radius but gives visual rhythm without touching layout.
- **`levels/index.js` already has 5 distinct gradients** (`cheese→swiss-red`, `swiss-red-dark→alp-900`, `swiss-red→wood-700`, `wood-600→swiss-red-dark`, `swiss-red via wood-700 to alp-900`) but this variety exists only on `LevelMap`/`LevelCoverArt` — the rest of the app (`Dashboard.jsx`, nav) stays monochrome red/white/alp. Reuse 2-3 of these same gradients as small accent strips (e.g. top border or icon-chip background) on dashboard stat cards and `StreakCounter.jsx` so the palette feels consistent app-wide, not confined to one screen.
- **Nav (`NavBar.jsx`) active state is a flat `bg-swiss-red/10 text-swiss-red` pill** — fine but static. Add a `transition-transform` + subtle `motion.span` (Framer Motion is already a dependency) that scales/fades the active pill in on route change — a `layoutId` shared-element transition between nav items reads as polished, not childish, and costs ~10 lines.
- **No illustrated/iconic section headers** — headings like "Tu ruta A1 → C2" (`App.jsx` line 63) are plain text. Add a small emoji-free line icon or a tiny wood/cheese-colored badge (e.g. a circular `bg-cheese-100 text-cheese-700` chip with a Lucide/Heroicons glyph) beside major section titles — signals "editorial/app" rather than "form," without becoming cartoonish.
- **Background is uniform `bg-alp-50` everywhere** (`App.jsx`) — flat and a bit sterile for a "fun" positioning. Add a very subtle repeating SVG topographic-line or cross-hatch pattern at ~3-4% opacity in `alp-200`/`wood-200` behind the main content area (CSS `background-image` on the outer wrapper), evoking "alpine map" without being noisy or reading as decoration aimed at kids.
- **Streak/gamification elements (`StreakCounter.jsx`) have no motion payoff** — a streak increment or level-up should get a one-time celebratory micro-animation (confetti-lite using existing Framer Motion, cheese/swiss-red colored dots, 400ms, no sound) rather than a static number change — this is the single highest-leverage "fun but adult" touch since it's tied to achievement, not decoration.

## Legibilidad y accesibilidad multi-edad

- **Set a body text floor of 16px (`text-base`), not `text-sm`** — audit any `text-sm`/`text-xs` used for actual reading content (lesson explanations, culture notes) vs. labels/timestamps; reserve `text-xs`/`text-sm` strictly for metadata, never for sentence-length content.
- **Line-height**: ensure body copy uses `leading-relaxed` (1.625) rather than default `leading-normal` — meaningfully easier for 55+ readers on longer lesson text blocks, negligible visual cost for younger users.
- **Tap targets**: `.btn-primary`/`.btn-secondary` currently use `px-5 py-3` — confirm rendered height clears **44px minimum** (Apple/WCAG target size); with `font-display font-semibold` at default line-height this is likely ~46-48px, so it's probably fine, but the mobile bottom-nav icons in `NavBar.jsx` (`py-2` only, no explicit height) should get an explicit `min-h-[44px] min-w-[44px]` per nav item to guarantee the target regardless of icon size.
- **Contrast**: avoid `text-alp-400` or `text-alp-500` for any text under ~14px — both are under 4.5:1 on `bg-alp-50`/white in some renders; standardize secondary text to `text-alp-600` (already used in `NavBar.jsx`) as the one "muted" token app-wide, and reserve `alp-400`/`alp-500` strictly for decorative icons/borders, never text.
- **cheese-300/400 as text color** — flag anywhere yellow is used as foreground text on white/alp-50 (e.g. badges, "new" labels) — contrast ratio is poor at any size; always pair `cheese` as a *background* fill with `alp-900` or `wood-900` text on top, never as text-on-light-bg.
- **Font size toggle — yes, recommend it.** Given the explicit teen-to-55+ range, add a lightweight "Tamaño de texto" control (3 steps: Normal / Grande / Muy grande, mapped to a `data-text-size` attribute on `<html>` that scales a CSS custom property `--text-scale` multiplying base rem sizing, or simpler: toggles a `text-lg`-equivalent class on the root). Place it in a **Settings/Ajustes screen** (not floating on every screen, which would look accessibility-app-y) — likely alongside a future dark-mode toggle, both as simple labeled switches/segmented controls, keeping the main UI chrome uncluttered for the default reader.
- **Font loading gap**: `font-display`/`font-body` reference Poppins/Inter but there's no Google Fonts `<link>` in `index.html` yet — every user is currently seeing system-font fallback, which quietly undermines both legibility tuning (fallback fonts weren't chosen for x-height/spacing) and the intended "warm but grown-up" typographic voice. Fix in `index.html` `<head>` with a preconnect + swap-display font link (flagged again below since it's also a "unfinished" item).

## Detalles que se sienten "a medio terminar"

- **Missing Google Fonts import** — `font-display: 'Poppins'` / `font-body: 'Inter'` are declared in Tailwind config but never loaded (confirmed: no `fonts.googleapis.com` reference anywhere in `index.html` or `src`). Every heading/button is silently falling back to the OS system font, which is the single biggest "why does this look generic" culprit. Fix: add to `index.html` `<head>`:
  `<link rel="preconnect" href="https://fonts.googleapis.com">`
  `<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>`
  `<link href="https://fonts.googleapis.com/css2?family=Poppins:wght@500;600;700&family=Inter:wght@400;500;600&display=swap" rel="stylesheet">`
- **Nav is a single flat color with no depth** — `NavBar.jsx` sidebar/bottom-bar are plain `bg-white border-*`. Add `shadow-sm` to the bottom mobile nav (it currently has only a top border, so on some backgrounds it can look like it's floating with no separation) and consider a 2px `bg-gradient-to-r from-swiss-red to-cheese-400` accent line pinned to the very top of the sidebar/bottom bar as a subtle brand flourish — a one-line addition with outsized "finished" effect.
- **`shadow-card` is presumably a single flat shadow token reused everywhere** — worth checking `tailwind.config.js` `boxShadow.card` value; if it's a plain `0 1px 3px rgba(0,0,0,.1)`-style shadow, it will look identical on every card regardless of elevation/emphasis. Add a second `shadow-card-lg` for "hero"/featured cards (the dashboard current-lesson card, level-up modals) so important elements visually outrank routine ones.
- **No empty-state treatment implied anywhere** (no `EmptyState` component found under `src/components/ui`) — first-run dashboard, "no lessons completed yet," search-with-no-results, etc. likely just render blank or a raw message. Add one reusable `EmptyState` component (icon/illustration + short copy + primary CTA) using existing `wood`/`cheese` tones — this is a very common "half-finished" tell in student-facing apps.
- **`.btn-secondary` border (`border-alp-200`) is quite low-contrast on the `bg-alp-50` page background** — the button nearly disappears against the page in bright/washed lighting. Bump to `border-alp-300` for a more defined, "designed" edge without changing the palette.
- **No focus-visible ring defined on `.btn-primary`/`.btn-secondary`/nav items** — keyboard/screen-reader users get browser-default (often invisible on colored buttons) outlines. Add `focus-visible:ring-2 focus-visible:ring-swiss-red/50 focus-visible:ring-offset-2` to both button classes and nav item classes — small addition, closes an accessibility gap that also happens to look unpolished when tabbing through.
- **Rounded corner token (`rounded-xl2`) used everywhere with no variation** — every card/button has the exact same radius, which can read as templated. Consider a slightly larger radius (`rounded-2xl` / `rounded-3xl`) specifically for the hero dashboard card and level-map tiles vs. the standard `.card`/buttons, to create a visual hierarchy of "featured" vs "routine" surfaces.
